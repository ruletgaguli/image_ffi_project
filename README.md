# image_ffi_project

## Проектная работа модуля 4. Обработчик изображений с плагинами

CLI загружает изображение, преобразует его в RGBA8, вызывает динамический плагин через C ABI и сохраняет результат в PNG. Входной формат определяется по содержимому; поддерживаются PNG, JPEG, BMP, GIF, WebP и TIFF.

В Cargo workspace четыре крейта:

- `image_processor` — CLI на clap, чтение и сохранение через image, загрузчик на libloading;
- `mirror_plugin` — динамическая библиотека `mirror`, отражение по горизонтали и вертикали;
- `blur_plugin` — динамическая библиотека `blur`, повторяемое размытие;
- `plugin_interface` — общая сигнатура FFI, проверка размеров, разбор пар параметров и перехват паник.

Алгоритмы плагинов работают с обычными срезами `&mut [u8]` и отдельно тестируются без FFI. Основной API содержит одну функцию `process_image(width, height, rgba_data, params)` с соглашением вызова `extern "C"`; оба плагина собраны как `cdylib`.

## Сборка

Нужны Rust 1.88 или новее и стандартный для платформы линкер. На macOS установите инструменты командой `xcode-select --install`; на Linux нужен C-компилятор и инструменты сборки, на Windows — инструменты соответствующего Rust toolchain. Сторонние системные библиотеки и базы данных не нужны.

Из корня `image_ffi_project`:

```bash
cargo build --workspace
```

Сборка создаёт бинарь и две библиотеки в `target/debug`:

| ОС | mirror | blur |
| --- | --- | --- |
| Linux | `libmirror.so` | `libblur.so` |
| macOS | `libmirror.dylib` | `libblur.dylib` |
| Windows | `mirror.dll` | `blur.dll` |

Одного `cargo run -p image_processor` недостаточно для первой сборки плагинов: они загружаются во время выполнения, а не входят в зависимости бинаря. `Cargo.lock` включён в репозиторий для воспроизводимости зависимостей.

## Запуск

В репозитории есть небольшое асимметричное изображение `input.png` и файлы параметров.

```bash
cargo run -p image_processor -- \
  --input input.png \
  --output out_mirror.png \
  --plugin mirror \
  --params params/mirror.txt

cargo run -p image_processor -- \
  --input input.png \
  --output out_blur.png \
  --plugin blur \
  --params params/blur.txt
```

Все четыре аргумента обязательны. Запуск без аргументов показывает справку. `--plugin` принимает голое имя, например `mirror`, а `--plugin-path` задаёт каталог библиотек, по умолчанию `target/debug`. Пути относительно текущего рабочего каталога. Выходной файл всегда содержит PNG, независимо от расширения.

Для release-сборки:

```bash
cargo build --workspace --release
cargo run -p image_processor --release -- \
  --input input.png --output out_mirror.png \
  --plugin mirror --params params/mirror.txt \
  --plugin-path target/release
```

## Параметры

Файлы в UTF-8 содержат пары `ключ=значение`, разделённые запятыми или переводами строк. Пробелы вокруг ключей и значений допустимы. Отсутствующие ключи получают значения по умолчанию. Пустой файл, неизвестные и повторные ключи, пропущенные значения и неверные типы отклоняются.

| Плагин | Ключ | Тип | По умолчанию |
| --- | --- | --- | --- |
| mirror | `horizontal` | `true` или `false` | `true` |
| mirror | `vertical` | `true` или `false` | `false` |
| blur | `radius` | целое неотрицательное `u32` | `1` |
| blur | `iterations` | целое неотрицательное `u32` | `1` |

`horizontal=true` меняет местами левую и правую стороны; `vertical=true` — верх и низ. Оба `false` оставляют изображение неизменным.

Размытие выполняет горизонтальное и вертикальное усреднение скользящим окном; за пределами изображения окно обрезается. В каждом проходе результат округляется вниз до целого байта. Усредняются все четыре канала, включая alpha. Радиус, превышающий размер строки, охватывает строку целиком. Одна итерация состоит из двух проходов; `radius=0` или `iterations=0` не меняют изображение. Время обработки линейно по числу пикселей и итераций, а не по площади окна.

## Безопасность и ошибки

Загружайте только доверенные плагины с указанным ABI: динамическая библиотека исполняет код внутри процесса, `libloading` не создаёт изолированную среду и не может проверить сигнатуру символа. Публичные операции загрузки в Rust помечены `unsafe` и документируют этот контракт.

Хост проверяет длину `width * height * 4` с защитой от переполнения. `Library`, `CString` и буфер хоста живут до завершения вызова, плагин не сохраняет и не освобождает переданные указатели. Ненулевой чужой указатель невозможно проверить на действительный размер памяти: его валидность обеспечивает вызывающий код.

В каждом плагине общий адаптер выполняет обработку внутри `catch_unwind` на рабочей копии. При ошибке разбора или обработки либо перехваченной панике исходный буфер не меняется. Плагин пишет причину в stderr. Сборка использует `panic = "unwind"`; принудительное завершение процесса и отказ выделения памяти на уровне системы не перехватываются `catch_unwind`.

Заданный API возвращает `void`, поэтому хост не получает отдельного статуса обработки от плагина. Если плагин отклонил параметры, CLI сохранит неизменённое изображение и завершится успешно; причину смотрите в stderr. Ошибки самого хоста — отсутствующий файл, повреждённое изображение, неверная библиотека, отсутствующий символ, NUL в параметрах и ошибки сохранения — дают ненулевой код завершения.

`RUST_LOG=debug` включает диагностические сообщения хоста. Для Windows задайте эту переменную способом, принятым в вашей оболочке.

## Проверки

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets
```

Тесты проверяют парсинг обоих плагинов, отражение буфера 2x2 по каждой оси и обеим сразу, размытие однородного изображения и яркого центра 3x3, нулевые параметры, границы буфера, откат при ошибке и панике, ошибки CLI и загрузчика.

После двух команд обработки из раздела «Запуск» можно проверить выходные изображения автоматически:

```bash
cargo run -p image_processor --example verify_results
cargo run -p image_processor --example verify_plugin_contract
```

Первая проверка сравнивает каждый пиксель отражения с исходным изображением, проверяет размеры и уменьшение резких переходов после размытия. Вторая копирует настоящие библиотеки во временный каталог, проверяет `--plugin-path`, результат обработки маленького PNG и неизменность буфера при неверных параметрах. Она требует предварительного `cargo build --workspace`. PNG-пример можно воспроизвести командой `cargo run -p image_processor --example generate_sample`.

GitHub Actions запускает форматирование и Clippy при `push` и `pull_request`. После успешного lint запускаются сборка workspace, тесты и реальные CLI-сценарии обоих плагинов с проверкой выходных PNG.

Соответствие пунктам ТЗ описано в [CHECKLIST.md](CHECKLIST.md).
